# Журнал выводов

Что понял на каждом этапе и что сделал бы иначе. Оригинал для сравнения — `vladilenm/modern-second-brain`.

## Этап 0–1. Нить: сессии Claude Code → SQLite → поиск → MCP

**Что сделано.** `brain sync` читает `~/.claude/projects/*/*.jsonl`, `brain search` ищет через FTS5,
`brain mcp` отдаёт Claude два инструмента: `search` и `get_record`.

**Формат сессий Claude Code.**
- Одна строка — одно событие. Типов много (`attachment`, `system`, `queue-operation`, `cost-state`…),
  разговор — только `user` и `assistant`.
- `content` бывает строкой или списком блоков. Нужны блоки `text`; `thinking` — рассуждения модели,
  `tool_use`/`tool_result` — работа инструментов. Реплика `user`, где только `tool_result`, — не слова человека.
- Подагенты лежат в `<session>/subagents/` — побочные ветки.

**Находки на реальных данных (в тестах на выдуманных их бы не было):**
1. *Одна сессия — несколько файлов.* Если в разговоре меняется рабочая папка, Claude Code продолжает
   ту же сессию (тот же id) в папке нового проекта. Ключ по имени файла давал коллизию: второй файл
   молча перезаписывал первый. Решение: группировать файлы по id сессии.
2. *Продолжение копирует историю.* Новый файл начинается с полной копии прежних событий (те же `uuid`,
   но другой `cwd`). Без дедупликации разговор попадал в базу дважды. Решение: склеивать файлы
   от старого к новому и выкидывать повторы по `uuid`.

**MCP SDK 2.x.** `FastMCP` переименован в `MCPServer` (`mcp.server.mcpserver`), поля моделей —
в snake_case (`read_only_hint`, `structured_content`). Схему параметров инструмента SDK строит
из аннотаций типов функции, описание — из docstring. У автора протокол написан руками (~150 строк).

**Отличия от оригинала, которые стоит разобрать дальше:**
- Токенизатор: у нас стандартный `unicode61` (целые слова), у автора `trigram` (подстроки) —
  «клуб» находит «клуба». Для русского это важно → этап 2.
- Синхронизация перечитывает всё каждый раз. У автора — только изменившиеся файлы и после
  30 минут тишины → этап 4.
- Ранжирование — голый bm25 без весов полей и свежести → этап 2.
- `with sqlite3.connect(...)` коммитит транзакцию, но не закрывает соединение. Пока не мешает.
